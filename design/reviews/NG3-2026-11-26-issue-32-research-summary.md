## 1. Что решаем

Убрать projectholder из транспортного и диспетчерского цикла, но оставить в цикле проектных решений и предоставления полномочий. Предпочтительно сохранять именно существующих экспертов в обычном ChatGPT (их проектный контекст и текущие чаты), а не только вызывать модель того же класса. Linux VM и не более примерно одного внепланового вмешательства в сутки — предпочтения, не жесткие ограничения ([holder](https://github.com/abyssdigger/vpn-gateway/issues/32#issuecomment-7175366698)). Work исключен по расходу квоты/стоимости ([решение](https://github.com/abyssdigger/vpn-gateway/issues/32#issuecomment-7174310591)). Предыдущий ID execution-gates trial завершен, не смешивать с этим исследованием.

**Два независимых пробела:** (1) O-CONTINUITY — достаточно ли точно конкретная долгоживущая chat incarnation применяет актуальное состояние при новом turn после terminal; (2) O-ACTIVATE — способен ли внешний сигнал без ручного сообщения инициировать такой turn. Работающий межэкспертный транспорт в активном turn не доказывает ни одного свойства в требуемой композиции. Ручной baseline R-SEM проверяет первое, не второе. Основание: #7176182393, #7176192880, #7176208539.

## 3. Гипотеза минимального транспорта (не проект реализации)

GitHub Issue + версионированные артефакты → детерминированная локальная проекция → уровень готовности (не один wake на comment) → разрешенный адаптер запуска → внешний ACK. Не вводить отдельный брокер, если хватает локального процесса и read-only polling. Webhook/Actions — альтернативы, если появится обоснованная потребность.

- Дедупликация по logical message ID, physical comment ID и хешу первого принятого тела; изменения/удаления уже принятого источника — конфликт, а не молчаливое перепроигрывание. Issue изменяем; не immutable event store. Пагинация, сверка пропусков, повторное чтение, ETag, backoff; прочитанное != обработанное != завершенное.
- Логическая роль эксперта, incarnation конкретного чата и capability profile разделены. Текущая incarnation — одна на роль, старая не принимает новые задачи. Фиксируются protocol revision и SHA governing docs; новая версия требует сверки/перечитывания, несовместимая — остановки.
- Состояния работы, доставки, gate и incarnation ортогональны. DORMANT — намерение завершиться, не доказательство terminal. ACK — внешнее подтверждение обработки конкретного wake, не гарантия завершения turn. До подтвержденной границы Send повтор возможен; после возможной отправки без ACK — AMBIGUOUS, сверка, без автоматической повторной отправки. Не обещать exactly-once.
- Незапланированный обрыв до DORMANT, конфликт version/frontier, auth challenge, потеря вкладки — явное восстановление/эскалация, не автоматическое расширение полномочий. Локальные сведения о доставке не всегда восстанавливаются из GitHub.
- Автоматический сигнал не может выдавать себя за распоряжение projectholder. Решение по продукту в CONTROL не расширяет write/tool authority. Прямой holder grant и PRE_MUTATION_GATE остаются самостоятельными условиями.
- Linux VM предпочтительна; минимум привилегий, обычная browser sandbox, отдельный непривилегированный пользователь и профиль, отсутствие секретов в публичном Issue. Не обходить login/session restrictions. Резидентная страница — штатный путь гипотезы; холодный запуск/перезапуск — отдельное восстановление. Вкладки одного профиля разделяют storage; не считать их изолированными учетными записями.
- Локальная модель — необязательная помощь при диагностике, классификации и подготовке capsule, только с детерминированной проверкой. Не принимать ею решения о Send, маршрутизации, полномочиях или смене incarnation.

Основания: #7175320780, #7175456494, #7175465164, #7175565896, #7175607435, #7175766090, #7175852051, #7175866045, #7175904275, #7175964188. Аналоги actor/workflow (Orleans, Dapr, LangGraph) — источники паттернов, не доказательство поведения ChatGPT.

## 4. Сохранение контекста и ограничение роста журнала

Три слоя: (1) конкретная chat incarnation — рабочая память; (2) GitHub + артефакты — долговременные решения, открытые обязательства, evidence; (3) локальный индекс/очередь — производные данные и собственные факты доставки. Не копировать весь чат в следующий чат и не считать Project Memory точным реестром.

- Двухступенчатое чтение: компактный индекс message_id/refs/frontier, затем необходимые тела. В #32 уже наблюдалось 119 комментариев / 279120 символов тел, при этом 115 YAML-конвертов занимали 24293 символа (#7175820067). Это измерение, не универсальная оценка токенов.
- Typed capsule: действующие и отмененные решения, открытые обязательства, основания/ссылки, frontier, текущие артефакты/SHAs, capability requirements, отдельно истекшие разрешения. Верификация по поведению, не по пересказу. Native Branch/Project Source — способы переноса, не authoritative state. Автоматический overflow может терять контекст; точного доступного meter не установлено.
- Ротация крупными issue/epoch по необходимости, либо issue-per-obligation; родительские ссылки сохраняют причинность. Не архивировать/удалять исходные записи без отдельного решения. Никакого нового issue сейчас.
- Модель на локальной машине может подготовить черновик capsule или выявить аномалию; не устанавливает истинность фактов сама.

Основания: #7175304472, #7175692386, #7175713552, #7175820067, #7175851907, #7175917970, #7175954688.

## 6. Декабрьская развилка и практическая польза сейчас

**Не городить огород заранее.** В #32 зафиксированы [анонс изменения модели usage](https://github.com/abyssdigger/vpn-gateway/issues/32#issuecomment-7175668090) и [анонс переноса возможностей Work в основной ChatGPT](https://github.com/abyssdigger/vpn-gateway/issues/32#issuecomment-7175786966). В цитируемом анонсе: с декабря 2026 для Plus/Pro/Business планируется общий token-based allowance ChatGPT и Codex при переносе agentic Work capabilities в основной ChatGPT; Instant chat исключен из этого allowance; часть аккаунтов может перейти раньше. Конкретная дата доступности в аккаунте, фактический расход квоты и поддерживаемый exact-chat external wake не доказаны. Анонс не обещает MCP Events в ordinary Chat и не гарантирует исчезновение ограничений Work. Не считать анонс изменением принятого запрета Work.

Варианты решения:
- Сейчас: сводка + durable frontier, один вручную начатый batch, transport через Issue, decision inbox. Это уже снижает ручной копипаст, хотя не исключает ручной запуск.
- До тяжелой разработки: R-SEM, R-CAPS, при необходимости небольшой synthetic R-MECH; сохраняют ценность даже при смене платформенного адаптера; то же относится к readiness/mailbox, протоколу и восстановлению frontier.
- После появления декабрьских изменений: проверить фактическую доступность/квоту аккаунта и штатные wake/notification primitives; оценить, нужен ли вообще внешний механизм. Не ждать пассивно неопределенно долго, если holder предпочтет дешевые независимые проверки сейчас.
- Если native wake отсутствует и практическая потребность остается: оценить допустимые варианты; API/Codex как отдельные альтернативы при согласии holder на смену природы эксперта и стоимость.

### 6.1. Частичный результат и экономика внимания

Новый кандидат без автономного wake: read-only проекция формирует список `READY` ролей и отдельно открытых `DECISION` gates. Holder получает агрегированный сигнал, вручную открывает заранее известные чаты и посылает фиксированное разрешенное продолжение; содержимое task/result не копирует. Это уменьшает транспортные вмешательства, не подменяя проектные решения и authority. Native GitHub notification — только подсказка; saved issue filter/Projects view при будущем отдельном разрешении на gate issues/labels — необязательный comparator. Не расширять credential ради Notifications API; локальные chat URLs не публиковать в Issue.

Метрика: различать T_transport, T_orchestrate, T_decision, T_authority, T_maintenance. Более существенная единица — сеанс внимания holder, особенно незапланированный (`A_interrupt`), размер пачки (`A_batch_size`), ложные визиты (`A_false`), отдельно содержательные решения и задержка READY→attention. Автоматический shim должен оправдать добавленное обслуживание по сравнению с уже полезным ручным batch, а не со старым копипастом.

OBSERVED: срез #32 на 163 комментариях (#7176243264): 252 resolved distinct refs/handled edges, 101 межэкспертный, 30 явных handled cross-expert; максимальная упорядоченная цепочка refs — 26 смен роли, 100 соседних смен автора; 0 forward/unresolved refs. Срез 162 комментариев: 356900 символов тел, 33186 символов YAML envelopes (~9%). Это не число обязательных переходов/ручных wake и не latency: refs могут быть контекстными, source-chat input не наблюдается, timestamps connector null. Измерять фактическое число wake, прочитанных материальных inputs и holder attention отдельно.

Основания: #7176235435, #7176243264, #7176253292, #7176259476; [notification settings](https://docs.github.com/en/subscriptions-and-notifications/get-started/configuring-notifications), [email headers](https://docs.github.com/en/subscriptions-and-notifications/reference/email-notification-headers), [inbox filters](https://docs.github.com/en/subscriptions-and-notifications/reference/inbox-filters), [Notifications API](https://docs.github.com/en/rest/activity/notifications).

### 6.2. Локальная остановка не означает завершение совместной работы

INFERRED: аналог distributed termination detection ([Dijkstra–Scholten](https://www.cs.utexas.edu/~EWD/transcriptions/EWD06xx/EWD684.html), [Temporal Continue-as-New](https://docs.temporal.io/develop/go/workflows/continue-as-new)). Даже два пустых final reads не исключают позднее сообщение. `QUIESCENT_AT(cut)` — гипотетическая характеристика конкретного среза/epoch, не global completion и не доказательство terminal. Для фиксированной области работы нужны открытые obligations, semantic dispositions, явно обработанный frontier; late work остается READY и требует подтвержденного wake либо ручного запуска. Timeout/timebox/checkpoint не дают права закрыть обязательство. Без автономного запуска ledger обеспечивает сохранность, не прогресс.

Контрпример: A final read empty → B публикует work → A заканчивает turn → B ожидает A. Это причина не обещать unattended liveness. Разные бюджеты активных экспертов и коалесценция review batches допустимы как гипотезы; текущие loop/ID правила не изменены. Основание: #7176258012.

## 7. Процесс: отдельный открытый вопрос
