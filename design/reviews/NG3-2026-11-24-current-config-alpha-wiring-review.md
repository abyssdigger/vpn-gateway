# NG3 2026-11-24 — ревью подключения текущей конфигурации к alpha runtime

**Единица ревью:** рабочая загрузка `parse_current_config` без материализации Device Manager  
**Код:** `c1fc2069fc6d716f9cc09e565e70a71cbec6e090`  
**Архитектурное отражение:** `6843b9fe653ae70b8eecea3ad45028cd542a8d33`  
**Компонент:** A.002 ConfigurationAdapter

## Вердикт

**PASS — A.002 ПОЛНОСТЬЮ ПОДКЛЮЧЕН; УПРАВЛЯЕМЫЙ VPN НАМЕРЕННО FAIL-CLOSED ДО РЕАЛИЗАЦИИ A.012/D.001/D.002/D.003.**

## Findings и решения

### F1 — рабочий путь должен использовать текущий parser, а не исторический Release-1 parser

**Решение:** принято.

`AlphaPreparedPolicy.from_text` теперь всегда вызывает `parse_current_config`.
Для конфигурации без `managed_vpn` используется его совместимый базовый результат,
поэтому прежний внешний Device проходит тот же структурный и policy-путь, что раньше.

Исторический `parse_release1_config` остается отдельным публичным контрактом и не получил
новых полей.

### F2 — распознанное управляемое намерение нельзя молча игнорировать

**Решение:** принято.

Если `parse_current_config` возвращает хотя бы один управляемый Device,
`AlphaPreparedPolicy.from_text` завершает подготовку явным `AlphaRuntimeError`, содержащим
идентификаторы таких Devices.

Ошибка возникает до создания `AlphaPreparedPolicy`, до построения host-publication desired
state и тем более до controller/domain/network mutation. Поэтому не возникает ложного режима,
в котором пользователь передал управление VPN-GATE, а продукт продолжил ждать внешний
интерфейс как будто `managed_vpn` отсутствует.

### F3 — промежуточный fail-closed gate не является реализацией Device Manager

**Решение:** принято.

Этот блок не создает A.012, не читает секреты, не вызывает D.001, не выбирает WireGuard-пир
и не изменяет `AllowedIPs`. Он только подключает завершенную ответственность A.002 к
рабочему входу продукта.

Невыполненные обязанности остаются явно локализованы в A.012/D.001/D.002/D.003 и не
прикрываются новым статусом A.002.

### F4 — A.002 теперь может быть full по своим R7/R8-вкладам

**Решение:** принято.

Для A.002 реализованы и подключены:

- распознавание явного `managed_vpn`;
- сохранение внешнего режима при его отсутствии;
- каноническая нормализация WireGuard-пиров;
- вывод точного условия привязки;
- вывод разрешений UDP из транспортных точек пиров;
- вывод общих сетей из `Profile.destinations`;
- нормализация ссылок на секреты без чтения секретов.

Поэтому component-local статусы для `VPNG-U001-R1.R3.R7`,
`VPNG-U001-R1.R3.R7.R1` и `VPNG-U001-R1.R3.R8` изменены на [`full`].
Это не меняет общий статус требований: обязательные downstream-вклады по-прежнему
нематериализованы.

## Итог

A.002 больше не является блокером будущего Device Manager.

Следующая предметная единица должна материализовать A.012 и/или нижнюю D.001 границу. До
этого управляемая конфигурация остается осознанно неподдерживаемой к исполнению, а не
неизвестной или молча игнорируемой.
