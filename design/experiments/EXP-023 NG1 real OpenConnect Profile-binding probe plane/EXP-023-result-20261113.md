## Observations

### Isolated primary probe plane

Installed selector:

```text
22023: from all to 172.21.201.19 oif vpns00 uidrange 0-0 ipproto icmp lookup 6023
```

Dedicated table:

```text
unreachable default metric 42760
172.21.201.19 dev vpns00 scope link
```

Selector-specific lookup:

```text
172.21.201.19 dev vpns00 table 6023 src 172.20.130.1 uid 0
```

The ordinary host route remained outside the probe plane:

```text
172.21.201.19 via 192.168.201.1 dev ens18 src 192.168.201.107
```

### Primary-only data-path outage

A temporary FORWARD DROP to the endpoint was inserted on remote client `pri` while both
OpenConnect sessions remained connected.

Observed simultaneously:

- primary probe through `vpns00`: **FAIL**, rc=1, 100% packet loss;
- secondary probe through `vpns01`: **PASS**;
- `vpns00` remained present;
- `vpns00` retained `IFF_UP` and `LOWER_UP`;
- primary ifindex remained `43`.

This proves that the primary active condition did not escape through the alternate live
OpenConnect path.

### Recovery

After removing the temporary DROP on `pri`, the isolated primary probe recovered on the
same server-side binding:

```text
PASS E: isolated condition recovered on the same real OpenConnect binding
EXP_023_REAL_OPENCONNECT_PROBE_PLANE=PASS
```

## Decision

EXP-023 validates the EXP-022 isolated control-plane primitive on the real dual-OpenConnect
stand:

- Profile-binding active probe traffic can be isolated from ordinary host/payload routing;
- a primary data-path failure can be detected while the OpenConnect binding remains
  present and administratively UP;
- a second live OC path does not create a false positive for a probe bound to the failed
  primary path;
- recovery can be detected on the same binding without forcing binding recreation.

Therefore the remaining availability work is no longer a Linux/OpenConnect routing
feasibility question. It is now product/runtime policy: configuration grammar, scheduler,
timing and hysteresis, condition composition, diagnostics, and coordinated ON/OFF
materialization of Profile-specific route/firewall/NAT state.
