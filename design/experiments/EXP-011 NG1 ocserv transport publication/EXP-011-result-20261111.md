# EXP-011 live result — 2026-11-11

Status: **COMPLETE — PASS**

## Environment

- test ocserv host: `192.168.201.107`;
- normal external endpoint: TCP/UDP `44443`;
- ROU experiment namespace: `vg-exp011`;
- host veth: `exp11h` = `192.0.2.1/30`;
- namespace veth: `host0` = `192.0.2.2/30`;
- temporary ocserv listener: `192.0.2.2:44443`;
- publication relay: host `:44443` -> namespace `192.0.2.2:44443`.

The normal test `ocserv.service` was stopped for the experiment and restarted afterwards.
The original ocserv configuration was not modified.

## Observations

Before the experiment the normal server had two connected clients:

    pri  192.168.201.108 -> 172.20.130.6
    sec  192.168.201.199 -> 172.20.130.5

After the ROU publication stack replaced the host listener, both clients automatically
reconnected to the unchanged endpoint `endpoint.loc:44443`.

### H1 — TCP/TLS/CSTP publication

Relay evidence included:

    TCP_ACCEPT peer=192.168.201.108:53084
    TCP_CONNECT target=192.0.2.2:44443
    TCP_ACCEPT peer=192.168.201.199:37768
    TCP_CONNECT target=192.0.2.2:44443

Client `pri` reported:

    Connected to HTTPS on endpoint.loc ...
    Got CONNECT response: HTTP/1.1 200 CONNECTED
    CSTP connected.

**H1: PASS.**

### H2 — UDP/DTLS publication

Relay evidence included bidirectional UDP:

    UDP_PEER peer=192.168.201.108:46525
    UDP_C2S bytes=168
    UDP_S2C bytes=108
    ...
    UDP_C2S bytes=1472
    UDP_S2C bytes=1472

Client `pri` reported:

    Established DTLS connection (using GnuTLS).
    Configured as 172.20.130.6, with SSL connected and DTLS connected

Experimental occtl state showed:

    pri ... 172.20.130.6 vpns00 ... (AES-256-GCM) connected

**H2: PASS.**

The proof relay intentionally maintains only one UDP peer association. With both real
clients connected simultaneously, `sec` showed `(no-dtls)` while `pri` retained DTLS.
This is consistent with the declared one-client UDP scope of the experimental relay and is
not a failure of the publication abstraction. A production relay must maintain independent
per-peer UDP associations.

### H3 — VPN interface namespace ownership

Inside `vg-exp011`:

    vpns00  172.20.130.1 peer 172.20.130.6/32
    vpns01  172.20.130.1 peer 172.20.130.5/32
    host0   192.0.2.2/30

In the main namespace the matching check showed only:

    exp11h  192.0.2.1/30

No `vpns00` or `vpns01` interface escaped into the main namespace.

**H3: PASS.**

### H4 — original server configuration preservation

The normal host ocserv was deliberately stopped. EXP-011 used a derived temporary
configuration and did not modify the original configuration. After cleanup the normal
service was started again and both clients reconnected successfully.

**H4: PASS.**

### H5 — cleanup

After Ctrl-C:

- `vg-exp011` absent;
- `exp11h` absent;
- host TCP/UDP `44443` publication listeners absent.

The normal `ocserv.service` was then started successfully on `44443`; both clients
reconnected.

**H5: PASS.**

## Decision

**EXP-011: COMPLETE — PASS.**

A real OpenConnect/ocserv endpoint can operate unchanged behind the NG1 ROU publication
boundary:

    unchanged client endpoint :44443
        -> ROU-owned host TCP/UDP sockets
        -> transport relay
        -> ocserv inside private ROU netns
        -> vpnsXX interfaces inside the same netns

Both CSTP/TLS and DTLS were proven through the boundary. This closes the real-protocol
publication prerequisite for the first executable ROU prototype.

Arbitrary external/internal port translation remains a separate protocol-level question.
