# EXP-053 result — host-side conntrack return steering

**Status:** COMPLETE — PASS

## Verdict

**PASS.**

Linux can use host-side conntrack state to remember that a remote-initiated flow entered from
the VPN-GATE managed stack and steer the reverse packets back into that stack without any
destination-specific route for the remote prefix in the host main table.

The result covers both required host-boundary cases:

1. forwarded reply from an ordinary LAN host;
2. reply generated locally by the host itself.

It does not prove multi-path pinning inside the managed namespace and does not replace
historical EXP-014.

## Observed evidence

The privileged CI run emitted:

```text
EXP053_NO_REMOTE_MAIN_ROUTE=PASS
EXP053_ROUTE_PRECONDITION=PASS
EXP053_FORWARDED_REPLY=PASS
EXP053_HOST_LOCAL_REPLY=PASS
EXP053_NO_REMOTE_MAIN_ROUTE=PASS
EXP053_RESULT=PASS
```

The route precondition deliberately made unmarked lookup for the remote address use the
ordinary LAN default, while `fwmark 0x53` selected a dedicated table whose default points
through the managed-stack boundary.

Therefore the successful reverse path cannot be attributed to a hidden host route for the
remote prefix.

## Proven mechanism

The successful lower mechanism is:

```text
remote-initiated packet enters host from managed boundary
    -> host PREROUTING stamps ct mark

reverse packet:
    forwarded reply
        -> PREROUTING restores ct mark to packet mark
    host-local reply
        -> nft type route OUTPUT restores ct mark to packet mark

packet mark
    -> RPDB
    -> dedicated host-boundary table
    -> managed-stack boundary
```

The host main default route remains ordinary.

## Architectural consequence

This evidence permits, but does not itself require, the following Release-1 split:

- `outbound`: host bootstrap routing is required to inject the initiating packet into the
  managed stack;
- `inbound`: remote-destination host bootstrap routing is not required for return traffic
  when stateful return steering is enabled;
- `bidirectional`: bootstrap routing is required for ordinary-side initiation; the same
  route may also carry inbound return traffic if an explicit route-return mode is selected.

A configuration escape hatch may select route-based return instead of host-side conntrack
return steering. That user-facing semantic must be separately accepted and named; EXP-053
does not mandate one spelling.

## Failure boundary

If stateful host return steering is unavailable or intentionally disabled, the conservative
fallback remains ordinary host routing toward the managed boundary, analogous to conventional
VPN clients that install routes for remote networks.
