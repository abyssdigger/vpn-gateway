## Architectural conclusion

The selected implementation satisfies Profile source-identity translation using existing
managed Profile flow association, the existing managed postrouting owner, and host
managed-routing reverse reachability. Shared administrative identities do not collapse
Profile identity inside STACK, and no host-side NAT/behavior-lane carrier is required.
## Supersession / coverage transition

**Supersedes:** EXP-064 **for the current Profile-SNAT applicability/return architecture**.

Previous coverage:

- after EXP-063 rejected transient cross-boundary Profile-tag handoff, EXP-064 proved a
  four-class host behavior-lane carrier for the then-selected host-side gateway-NAT and
  stateful/route-return design.

Current coverage:

- EXP-076 proves that Profile SNAT remains entirely inside STACK, selected by the existing
  Profile flow association after original-source policy;
- the host receives only the resulting IPv4 identity and needs no Profile/behavior metadata
  carrier;
- reverse traffic returns through the host managed route and STACK conntrack/flow affinity.

The coverage changed because host-side gateway NAT, stateful-return and `+route-return`
were removed from the architecture.

**Retains:** EXP-063 remains valid negative evidence that the tested transient packet-mark
handoff did not survive the old cross-namespace boundary as required. EXP-076 does not
reinterpret or supersede that technical failure; it removes the need for that carrier.



## Current requirement disposition

The core PASS remains acceptance evidence for Profile SNAT isolation, source identity,
translation ordering and preservation of Profile association inside STACK.

The host-route observations in this result are retained only as integration evidence for the
tested deployment. They do not make automatic host routing part of the core Profile-SNAT
contract. Host-side reachability to a translated identity may be supplied by a separate
host-routing helper or by administrator-managed routing.
