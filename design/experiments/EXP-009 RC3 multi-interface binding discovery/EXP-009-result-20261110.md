# EXP-009 — RC3 multi-interface binding discovery

**Запуск:** 2026-11-10  
**Статус:** IN PROGRESS — discovery PASS, route failover pending  
**Тип:** ручной live discovery experiment

## Условия

Два независимых OpenConnect client одновременно подключены к одному ocserv server:

```text
pri -> 172.20.130.6
sec -> 172.20.130.5
```

## Наблюдаемое состояние сервера

```text
=== ocserv users ===
      id     user    vhost             ip         vpn-ip device   since    dtls-cipher    status
   31612      sec  default 192.168.201.199   172.20.130.5 vpns01     6s  (AES-256-GCM) connected
   31214      pri  default 192.168.201.108   172.20.130.6 vpns00    45s  (AES-256-GCM) connected

=== vpns interfaces ===
vpns00           UNKNOWN        172.20.130.1 peer 172.20.130.6/32
vpns01           UNKNOWN        172.20.130.1 peer 172.20.130.5/32
```

## Промежуточный вывод

H1 PASS: одновременно исправные peers используют разные server-side runtime interfaces. Прежняя
модель одной concrete binding на profile не представляет это состояние.

Наблюдение также дает association evidence непосредственно в kernel address inventory:
exact interface + local IPv4 + point-to-point peer IPv4.

Общее архитектурное исправление зафиксировано в RC3 и в
`design/vpn-gateway-experiments.md`.
