## Environment

The experiment ran on a privileged GitHub Actions Ubuntu 26.04.1 runner using real Linux
network namespaces, kernel WireGuard interfaces, `wireguard-tools 1.0.20250521`,
`iproute2` and `ping`.

One client namespace contained one `wg0` and ten WireGuard peers A..J on ten independent
underlay links. Every peer permanently owned one unique in-tunnel probe `/32`:

`10.201.0.1/32 .. 10.201.0.10/32`.

All peers independently exposed the same payload address `10.77.0.1`. The shared candidate
ownership prefix was `10.77.0.0/24`.

The generated client base configuration contained the interface key, all ten peers, their
transport endpoints and only the ten permanent probe prefixes. It deliberately contained no
shared payload-prefix owner.

For unambiguous payload attribution, each peer namespace emitted ICMP replies with a unique
namespace-local IPv4 TTL. WireGuard transfer counters were retained only as secondary
transition observations because the ten-peer test demonstrated small unrelated counter
increments after prior probes.

## H1 — safe no-owner base configuration

PASS.

Fresh `wg0` state contained exactly the ten permanent probe prefixes and no
`10.77.0.0/24` owner:

```text
EXP088_BASE_STATE={
  A: 10.201.0.1/32,
  B: 10.201.0.2/32,
  C: 10.201.0.3/32,
  D: 10.201.0.4/32,
  E: 10.201.0.5/32,
  F: 10.201.0.6/32,
  G: 10.201.0.7/32,
  H: 10.201.0.8/32,
  I: 10.201.0.9/32,
  J: 10.201.0.10/32
}
EXP088_BASE_NO_OWNER=PASS
EXP088_TEN_PEER_PROBES=PASS
```

Each probe target returned the TTL assigned to its expected peer namespace.

## H2 — runtime shared-prefix selection

PASS.

The complete desired AllowedIPs state for all ten peers was applied with one
`wg set wg0 ...` invocation. Peer A became the shared-prefix owner without recreating
`wg0`, and real payload replies from `10.77.0.1` carried A's unique TTL.

```text
EXP088_INITIAL_SELECT=PASS
```

## H3 — ordered ten-peer failover

PASS.

The experiment sequentially disabled the underlay of the current owner A through I. Before
each switch it proved the current peer probe unavailable and the next peer probe reachable,
then applied and freshly verified complete AllowedIPs state.

Real payload moved in order:

`A -> B -> C -> D -> E -> F -> G -> H -> I -> J`.

```text
EXP088_ORDERED_FAILOVER=PASS
```

No interface recreation was used for these owner changes.

## H4 — reversible recovery

PASS.

After restoring the peer underlays, the shared prefix was moved back to A and real payload
again returned A's unique TTL.

```text
EXP088_RECOVERY=PASS
```

This proves lower-operation reversibility; it does not select product failback policy.

## H5 — full base restart removes dynamic ownership

PASS.

Before restart the client `wg0` ifindex was 2. The interface was deleted and recreated from
the unchanged generated base configuration; the new observed ifindex was 3.

After recreation:

- all ten permanent probe prefixes were restored;
- the shared `10.77.0.0/24` prefix belonged to no peer;
- payload to `10.77.0.1` was unavailable until a new owner was selected;
- all ten probe identities were usable again;
- evidence tied to the preceding experimental realization generation was rejected as stale.

```text
EXP088_RESTART_RESETS_OWNER=PASS
EXP088_IFINDEX_REUSE=NOT_OBSERVED
```

The ifindex observation is evidence from this run, not a product guarantee that Linux can
never reuse an ifindex.

## H6 — command submission is not confirmation

PASS.

Every successful owner change was followed by fresh
`wg show wg0 allowed-ips` observation and exact verification before the experimental
realization generation advanced.

A deliberately failing `wg set` against a missing interface did not change the confirmed
AllowedIPs state and did not advance the generation.

```text
EXP088_CONFIRMED_APPLY=PASS
EXP088_GENERATION_REJECTS_STALE=PASS
```

## H7 — observed live transition

OBSERVED — no packet loss in the tested A-to-B transition; no universal atomicity claim.

While 200 ICMP requests were sent continuously to the shared payload address, the experiment
applied the complete ten-peer desired state moving the shared prefix from A to B.

Observed record:

```text
EXP088_TRANSITION_OBSERVATION=
  lost_packets=0;
  confirm_ms=4.665;
  reply_peers=A:24,B:176;
  old_tx_bytes_during_confirm=0;
  new_tx_bytes_during_confirm=128;
  post_confirm_peer=B;
  post_confirm_old_tx_bytes=32;
  post_confirm_new_tx_bytes=2560
```

All 200 requests received replies. The unique TTL markers showed only the old owner A and new
owner B during the transition, and B exclusively in the post-confirmation payload burst.

The small post-confirmation old-peer transfer-counter delta is not used as payload identity:
the earlier ten-peer run demonstrated that transfer counters can receive small unrelated
increments after prior probes. TTL-tagged payload replies are the direct attribution evidence.

This one run does not establish a kernel/API guarantee that arbitrary multi-peer
`wg set` updates are transactionally atomic. It does establish that the tested complete-state
apply produced no observed loss or third-peer delivery and that fresh post-apply observation
can delimit the confirmed new realization.

```text

```

The ten-peer lower mechanism is feasible.

The evidence supports the following architecture inputs without selecting final component
names or user configuration:

1. one WireGuard interface may retain multiple ordered peer alternatives for one shared
   destination prefix;
2. permanent peer-specific probe prefixes belong to base WireGuard configuration;
3. shared payload-prefix ownership is separate runtime state;
4. owner changes do not require interface restart;
5. full base restart safely returns shared ownership to an unassigned state;
6. a realization generation must advance only after fresh confirmation of the new exact
   AllowedIPs state, so old availability evidence cannot survive a peer-owner change;
7. no additional traffic gate is justified solely by the observed normal transition, but
   absence of such a gate must not be described as a proven universal atomicity property.

The experiment does not implement a production Device Manager, define secret storage,
select systemd ownership, or define multi-prefix scheduling.
