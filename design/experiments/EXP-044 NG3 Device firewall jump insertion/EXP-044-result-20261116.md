```text

```

The test packet passed because the earlier Profile `accept` terminated evaluation before
the Device jump.

Observed base-chain order after `insert rule`:

```text

payload-forward-return
```

The same packet was then dropped by the Device child chain before reaching the Profile
allow.

## Consequence

A production Device-firewall mutation path must not use ordinary append for a new
`payload_forward` Device jump.

The minimum proven primitive is:

```text
insert rule ip vpn_gate payload_forward ...
```

which places the new jump before existing Profile rules in the tested target environment.

This avoids requiring a full `payload_forward` rebuild merely to introduce a Device
firewall jump.

## Scope limits

PASS does not yet authorize production mutation. A guarded Executor must still:

- confirm invariant scaffold/table ownership;
- classify all Device child chains/jumps it may mutate;
- preserve the forwarding barrier;
- remove stale jumps before stale child chains;
- create child chain/rules before exposing a jump to it;
- re-observe exact whole owned scope after each mutation phase;
- never re-enable forwarding merely because an nft command returned success.
