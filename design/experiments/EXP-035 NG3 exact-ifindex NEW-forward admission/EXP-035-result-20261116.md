## Packet assertions

- empty `payload_forward policy drop`: matching traffic denied;
- exact current host ingress + current VPN egress + in-prefix NEW packet:
  tested rule counter incremented;
- different ingress: counter delta 0;
- different egress while destination remained inside the prefix: counter delta 0;
- same ingress/egress with destination outside the prefix: counter delta 0;
- same-name replacement with a fresh conntrack tuple: stale old-oif rule
  counter delta 0.

The test deliberately supplied no return-flow allow rule. It used the rule
counter as authoritative evidence for NEW admission rather than claiming
successful bidirectional ping.

## Architectural consequence

The Linux/nft lower mechanism is viable for one outbound NEW-flow primitive:
exact current iif/oif generation plus IPv4 destination prefix plus `ct state new`.
The observer must normalize live symbolic interface operands and stale decimal
ifindices exactly as for the NAT evidence.

This does **not** prove or select:

- the complete Profile filter compiler;
- inbound NEW rule shape;
- established/related return-flow policy;
- longest-prefix arbitration across several Profiles;
- Device envelope intersection;
- probe policy composition;
- complete nft structural convergence or forwarding activation.

Those remain separate design/evidence gates. No user-facing syntax follows
from this experiment.
