# EXP-034 — результат точного удаления stale NAT-правила по handle

**Дата:** 2026-11-16  
**Среда:** GitHub Actions Ubuntu Linux privileged runner; одноразовый
network namespace, `iproute2` + `nftables`.  
**Run:** [NG3 Python 43859095573](https://github.com/abyssdigger/vpn-gateway/actions/runs/43859095573)  
**Source commit:** `3b7b6087c6cb1a00ab064740661f1bc60e0e6b57`

## Гипотеза

После исчезновения concrete egress (прежний `ifindex`) nft NAT rule,
созданный по exact-ifindex и содержащий принадлежащий продукту owner comment,
можно точно удалить по handle, не удаляя новое правило для одноименного
заменяющего interface. Команда удаления несуществующего handle обязана
завершиться без изменения фактического ruleset.

## Процедура

В проверенном netns установлено `net.ipv4.ip_forward=0`.
Созданы две veth-pairs; зарегистрирован `table ip vpn_gate` с exact owner
marker и invariant `payload_forward`/`payload_postrouting` scaffold.
Добавлено первое source-NAT правило с числовыми `meta iif/oif`,
наблюдаемое как current.

Затем `tun0` удалён и создан заново с тем же именем, но новым ifindex.
Старое правило обнаружено текущим observer как stale. Второе правило
создано для нового ifindex, old/new handle записаны независимо.

Команда `nft delete rule ip vpn_gate payload_postrouting handle <old>`
удалила только stale правило. Актуальный nft JSON повторно прочитан и
проверен: `confirmed = desired`, `stale = ()`, `conflicts = ()`,
`handles = (new_handle,)`. Затем ошибочное удаление заведомо
отсутствующего handle завершилось неуспешно, снимок nft объектов
остался неизменен. Барьер `ip_forward=0` перепроверен.

## Вывод и граница

**PASS для exact-handle delete на проверенной Linux/nft среде**:
удаление по идентификатору старого фактического правила не затрагивает
новое одноименное interface rule; missing handle не является
безусловным успехом и не меняет остальные правила.

Это доказательство внешнего механизма, не одобрение полноценного
`NetworkPolicyExecutor`: эксперименты не доказывают отсутствие
конкурирующих writers, полноту классификации остальных nft объектов,
атомарность составного structural transition, безопасное reopening
forwarding или автоматический recovery после любых частичных ошибок.
Эти условия остаются обязательными отдельными design/evidence gates.

Никаких изменений пользовательских требований/конфигурационной схемы
из результата не следует.
