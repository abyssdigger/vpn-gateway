## Proven facts

The old global preserve-main rule is not neutral outside helper scope: with an explicit
non-default route in `main`, it can resolve an unselected packet before a later
administrator RPDB rule that would otherwise run before the kernel's ordinary `main`
lookup.

Using the same `iif` selector on preserve-main and dispatch removes that interference:
unselected traffic reaches the administrator RPDB rule unchanged, while selected traffic
still gives explicit non-default `main` routes precedence over the helper table.

The experiment did not modify ordinary `main` routes.

## Acceptance consequence

The former global preserve-main peaceful lowering is rejected for selector scopes narrower
than `:any`. The accepted candidate is a per-selector preserve+dispatch pair. `:any`
naturally remains global because its selected scope is global ordinary-host traffic.

This is a correctness/non-interference fix for `VPNG0001-R2` and `VPNG0001-R2.R2`, not a
new user-visible routing mode.
