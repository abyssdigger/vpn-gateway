## Observed rule JSON

Current GitHub Linux/iproute2 6.19 numeric JSON for:

```text
priority 8192
uidrange 4242-4242
ipproto icmp
to 198.51.100.7/32
lookup 3221225472
```

was:

```json
{"dst":"198.51.100.7","ipproto":"ipproto-1","priority":8192,"src":"all","table":"3221225472","uid_end":4242,"uid_start":4242}
```

Important normalization facts:

- exact /32 destination is rendered as bare `dst`;
- exact UID range is represented by integer `uid_start` and `uid_end`;
- with `-N`, ICMP is rendered as `"ipproto-1"`;
- the high probe table remains a decimal string;
- `src="all"` remains explicit.

## Decision impact

EXP-065 does not introduce new product semantics. It supplies current lower evidence for the
probe-routing mechanism already recovered from EXP-022.

The earlier EXP-029 `fwmark/fwmask` probe rule remains valid evidence for the JSON form of a
marked RPDB rule, but it was a structural-inventory test surrogate and is not the selected
Release-1 probe-routing discriminator.

The authoritative probe-owner structural observer may now normalize the selected shape:

```text
uid_start + uid_end + ipproto + exact dst + reserved probe priority/table
```

and treat a reserved probe `fwmark/fwmask` shape as unsupported/stale ownership rather than
as current desired probe policy.
