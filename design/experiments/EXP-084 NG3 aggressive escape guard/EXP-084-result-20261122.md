# EXP-084 result — aggressive routing independent escape guard

**Date:** 2026-11-22  
**Technical result:** **PASS**  
**Workflow run:** `45038917448`  
**Job:** `linux-host-managed-routing`

## Proven

The experiment used the current aggressive host-routing lower realization for a managed
destination prefix and added a separate nftables guard in the ordinary HOST namespace.

The guard allowed a managed destination to leave only through the exact current managed
boundary; matching HOST OUTPUT/FORWARD traffic selected for any other egress was dropped.

Results:

- current aggressive routing converged and forwarded both local and forwarded managed traffic
  through the managed boundary: **PASS**;
- installing the guard did not disturb correctly routed managed traffic: **PASS**;
- an earlier foreign RPDB rule redirected route lookup for the same managed destination to an
  ordinary uplink, reproducing the EXP-081 bypass: **PASS**;
- with that foreign rule active, the independent guard blocked both local and forwarded
  managed traffic instead of allowing it to escape through the ordinary uplink: **PASS**;
- the existing routing-owner observation still reported its own lower state exact, confirming
  the EXP-081 observation gap: **PASS**;
- after removing the foreign rule, traffic resumed through the managed boundary while the
  guard remained installed: **PASS**.

The workflow also reran EXP-074, EXP-081, EXP-078, EXP-079 and EXP-080 successfully in the
same job.

## Architectural conclusion

The future aggressive helper should not rely on continuous observation alone to prevent
transient escape. Its active lower state can include two complementary postconditions:

1. desired managed routing sends the delegated destination scope to the managed boundary;
2. an independently owned escape guard forbids that same scope from leaving through a
   non-managed egress.

The routing Manager still needs fresh observation and recovery because the guard does not
repair routing and does not make an incorrect route healthy. But the safety property no longer
depends on detecting every external routing-policy change before the next packet.

This also gives `VPNG-U001-R5.R2.R3` a concrete helper-local fail-closed primitive that is
independent from the routing state whose correctness is in doubt. Broader public protective
mode remains a separate escalation target.
