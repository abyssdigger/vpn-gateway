## Proven

The experiment first reproduced the former route shape:

```text
<snat identity>/32 dev vpng0
```

Forward translation reached the ordinary side, but the reply failed because HOST attempted
neighbor resolution for the SNAT identity itself. The observed neighbor state was
`198.19.255.10 INCOMPLETE`.

The production host-routing owner then migrated the same identity to:

```text
<snat identity>/32 via <stack-service-address> dev vpng0 onlink
```

with no additional stack-local SNAT-identity address or proxy-neighbour owner.

## Architectural conclusion

Remote managed prefixes may remain gateway-less device routes, but a Profile SNAT identity
requires the already-owned STACK service address as an onlink next hop. This is sufficient for
L2 delivery while leaving the IP destination equal to the translated identity until managed
conntrack performs reverse SNAT.
