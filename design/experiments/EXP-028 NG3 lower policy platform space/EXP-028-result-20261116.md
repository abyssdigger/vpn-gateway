## What was proved

### H1 — high 32-bit routing-table pools

PASS.

The experiment successfully created, observed and used routes at both boundaries needed to
justify the declared half-open pools, including:

- payload first `0x80000000`;
- payload last `0xbfffffff`;
- probe first `0xc0000000`;
- probe last `0xffffffff`.

Therefore the allocator may classify the full declared table ranges rather than only the
first representative IDs.

### H2 — RPDB pool ordering and actual lookup

PASS.

Rules at:

- probe first `0x2000`;
- probe last `0x3fff`;
- payload first `0x4000`;
- payload last `0x5fff`;

were accepted and observed before the standard main rule at priority 32766.

Real route lookup selected the intended high-ID probe and payload tables.

### H3 — route protocol role markers

PASS.

Protocols 201 and 202 remained observable in the selected high-ID tables and protocol-filtered
route inventory returned the managed path route.

Historical RC/NG evidence for these values is therefore supported by a fresh NG3 combined
layout test rather than inherited by convention.

### H4 — metric extrema

PASS.

The experiment proved coexistence of:

- normal path metric `1`;
- terminal blackhole metric `0xffffffff`.

This gives the per-Profile allocator the maximum available metric headroom between ordinary
preference/scratch values and the terminal guard.

### H5 — dedicated nftables namespace

PASS.

`table ip vpn_gate` was created, observed through JSON inventory and deleted inside the
disposable namespace.

## Findings while establishing the evidence

### F1 — numeric route type representation changed

Initial harness logic expected `row["type"] == "blackhole"`.

Current GitHub runner iproute2 6.19 with `-N` reported:

```text
"type": "6"
```

for `RTN_BLACKHOLE`.

Disposition: harness corrected to normalize the kernel semantic route type. This is also
forward evidence for the future NG3 structural route inventory parser.

### F2 — payload forwarding lookup needed a representable ingress source

The first payload `route get ... iif host0 from 192.0.2.2` attempt had no local host0
subnet and was rejected by the kernel before policy lookup could be evaluated.

Disposition: the disposable harness now assigns `192.0.2.1/24` to host0. No production
layout value changed.

### F3 — experiment changes were not initially workflow-triggered

The initial workflow path filter covered NG3 Python and the workflow file, not EXP-028.

Disposition: both push and pull-request path filters now include the EXP-028 directory.

## Safety

All mutation occurred inside a disposable network namespace. Host routes, rules and nftables
state were not modified.

## Decision

The candidate is accepted as the current NG3 Linux `NetworkPolicyPlatformSpace`.

These values remain implementation constants below NetworkPolicyAdapter and are not added to
the user configuration.

A materially changed Linux/iproute2/nftables platform must rerun this gate.
