## Claim tested

EXP-069 tested whether a direct Linux metadata carrier can preserve an already-selected
stack-side behavior class across the existing cross-network-namespace veth into the
VPN-GATE-managed tambour, without adding a separate behavior-lane veth.

The experiment deliberately kept EXP-063's transient packet mark as a regression control
and broadened the tested carrier set. It also used IPv4 DSCP as an on-wire positive control,
not as an acceptable product carrier.

## NAT / cleanup interaction

The only surviving carrier was the on-wire DSCP positive control.

For that carrier, the managed-tambour ingress rule:

1. matched the exact DSCP value;
2. stored an internal tambour-owned NAT conntrack class;
3. cleared the original DSCP marker before ordinary host route processing.

Observed evidence:

```text
classified packets:      8
post-consume marker hits: 0
NAT first-packet hits:    1
```

The marked flow reached LAN with the host ordinary-side address `192.0.2.1`, proving
MASQUERADE. A neighboring unmarked flow reached LAN with the original source
`10.69.0.2`, and neither the classifier nor NAT counter increased for that control flow.

Thus the consume -> internal class -> gateway NAT sequence is mechanically viable when a
carrier does survive, and the cleanup point is early enough for the original carrier not to
leak into ordinary host-owned processing.

## Technical conclusion

For the directly nft-usable local metadata tested by EXP-069, **no local-only carrier
survived the cross-netns veth boundary**.

The only surviving tested field was IPv4 DSCP, which is part of the IP packet and therefore
has external sender/receiver semantics. EXP-069 intentionally does not select it as a
VPN-GATE carrier.

This result strengthens the technical reason for the current physical behavior-lane
fallback, but it does not by itself change the selected EXP-064 disposition or normative
architecture. Alternative mechanisms not tested here — for example explicit encapsulation,
VLAN/L2 coding, BPF side-channel state, or other topology carriers — remain separate design
spaces and would require their own evidence.
