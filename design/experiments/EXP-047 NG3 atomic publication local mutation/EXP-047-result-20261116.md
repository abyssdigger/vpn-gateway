One nft batch can install or remove the exact local publication INPUT/OUTPUT rules as one
transaction.

Confirmed behavior:

- publication traffic became available only after the add batch committed;
- an intentionally invalid second command caused the complete batch to fail;
- the valid first command from that failed batch was rolled back;
- one delete batch removed both exact local publication rules;
- payload-forward and payload-NAT owner objects remained unchanged.

## Consequence

The local publication owner class does not rely on the managed IPv4 ForwardingGate for
mutation safety. `stack_input` / `stack_output` affect local traffic even while
`ip_forward=0`.

The accepted mutation primitive is therefore one endpoint-scoped nft transaction plus fresh
exact postcondition observation:

```text
add/repair:
    one nft batch containing all missing exact rules for one endpoint

remove stale endpoint contribution:
    one nft batch deleting all observed stale handles for that endpoint
```

ForwardingGate may remain closed during combined convergence as an additional payload-plane
barrier, but it is not the correctness mechanism for local publication admission.

not authorize probe, loopback or generic integration exceptions.
