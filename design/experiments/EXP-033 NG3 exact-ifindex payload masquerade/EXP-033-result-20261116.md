## JSON representation finding

The rule was inserted using numeric ifindices.

While both interfaces existed, both ordinary and `-n` JSON inventory rendered meta
interface operands as names:

```json
{"match":{"left":{"meta":{"key":"iif"}},"op":"==","right":"e33gl-2347"}}
{"match":{"left":{"meta":{"key":"oif"}},"op":"==","right":"e33gr-2347"}}
```

After the old egress interface was deleted and a same-name/new-ifindex replacement created,
the stale rule rendered the egress operand as the old decimal-string index:

```json
{"match":{"left":{"meta":{"key":"oif"}},"op":"==","right":"9"}}
```

The new interface had ifindex `11`.

Thus nft JSON display is name-resolved when an index has a current name and falls back to the
numeric string when that index no longer resolves.
