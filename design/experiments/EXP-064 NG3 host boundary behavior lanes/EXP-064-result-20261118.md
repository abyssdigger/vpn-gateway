# EXP-064 result — fixed host-boundary behavior lanes

**Date:** 2026-11-18  
**Technical result:** **PASS**

## Proven

The tested Linux topology proves that the managed stack does not need to transfer arbitrary
Profile identity into the ordinary-host namespace in order to realize the accepted Release-1
host-side semantics.

A fixed behavior-lane carrier can encode only the two host-side behavior bits already present
in normalized Profile policy:

- stateful return steering enabled/disabled;
- ordinary-side gateway NAT enabled/disabled.

All four combinations were exercised successfully while the stack retained the real
per-Profile established-flow association.

The run also proved that:

- gateway NAT applies only to NAT-enabled forwarded ordinary-network traffic;
- host-local termination is not gateway-NATed;
- unrelated host-origin traffic is outside the gateway-NAT owner;
- route-return classes can use ordinary host routing;
- stateful-return classes can use host connection state and dedicated return steering;
- after the reply re-enters the managed stack, the existing stack-side Profile affinity
  restores the original VPN routing domain.
