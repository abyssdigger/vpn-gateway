## Proven facts

For Linux RPDB, a higher-priority rule

```text
iif <managed-boundary> goto <helper-exit>
```

combined with a helper-owned `nop` rule after all helper dispatch priorities skips the helper
range absolutely and then resumes ordinary RPDB processing.

The experiment proved both important cases:

- with an ordinary default route, STACK-origin traffic reaches that ordinary route instead of
  helper dispatch;
- after the ordinary default is removed, the same STACK-origin lookup fails as unroutable and
  still does not fall back into the helper table.

The JSON observer shape is stable enough for strict ownership: the bypass row exposes `iif`
plus `goto`, and the exit row exposes `nop`.

## Acceptance consequence

an absolute bypass. A table lookup that returns no route allows RPDB evaluation to continue;
therefore broad helper selectors could otherwise recapture STACK-origin traffic.

Release-1 peaceful helper and the postponed aggressive helper.
