# EXP-022 target result — PASS

Date: 2026-11-13  
Target: Debian 13  
Result: **PASS**

## Proven observations

1. Ordinary/main payload route to the test target remained on `alt0`.
2. Before the probe control plane existed, the dedicated bound probe on `vpn0` could not
   reach the routed target.
3. The combined RPDB selector

   ```text
   uidrange 65534-65534
   + ipproto icmp
   + to 203.0.113.22/32
   + oif vpn0
       -> lookup 6022
   ```

   selected the dedicated probe table.
4. The probe table routed the target only through `vpn0`, while ordinary payload continued
   to use `alt0`.
5. Unbound probe traffic and wrong-uid bound traffic could not consume the probe plane.
6. Breaking only the primary `vpn0` condition path made the probe fail while the alternate
   ordinary payload path remained live; the probe therefore did not escape through `alt0`.
7. Restoring the primary path recovered the probe without replacing the interface.
8. Same-name/new-ifindex recreation did not inherit working stale probe state; the probe
   became usable only after current control-plane refresh.
9. Exact numeric ifindex reuse is supported on the target.
10. Exact-ifindex reuse alone did not restore the complete probe plane because the dependent
    probe route had disappeared with the old interface.
11. Recreating only the probe route **did** reactivate the stale RPDB and nft rules when the
    new interface deliberately reused the old numeric ifindex:

    ```text
    EXACT_REUSE_STALE_RULE_NFT_REACTIVATED=1
    ```

12. A full refresh of current RPDB, route and nft probe state produced the expected working
    probe plane.

Final marker:

```text
EXP_022_ISOLATED_PROBE_PLANE=PASS
```

## Architectural consequence

The isolated availability-condition plane is viable:

- active probe traffic can be isolated from Profile payload routing;
- probe recovery can continue while a Profile-binding pair is OFF;
- alternate payload paths cannot turn a failed condition into a false positive;
- Profile payload routes do not need probe-only routes.

However, numeric ifindex is only a selector for a currently observed interface. It is not a
durable generation identifier.

Therefore a newly observed/recreated binding after an observation discontinuity must not
inherit an old control result or partially retained probe plane merely because
`(ifname, ifindex)` matches previous values. The current probe-plane generation must be
rebuilt and verified as a whole.

## Harness lessons

Three harness defects were found before the final PASS:

- missing alternate-path return route;
- Linux weak-host ARP made a loopback target appear directly reachable until
  `arp_ignore=1` was applied;
- failed ARP creates INCOMPLETE/FAILED neighbour-cache entries, so cache-entry presence is
  not reachability evidence.

Future experimental assertions should print the raw observable that caused a FAIL before
terminating.
