# EXP-089 — прямая базовая реализация управляемого WireGuard Device

**Статус:** PREPARED / UNPROVEN  
**Дата:** 2026-11-24

## Связь с требованиями

Эксперимент проверяет нижние предпосылки для:

- `VPNG-U001-R1.R3.R7` — явно управляемый VPN Device;
- `VPNG-U001-R1.R3.R7.R1` — отсутствие неявного усыновления внешнего VPN;
- `VPNG-U001-R1.R3.R7.R2` — подтверждаемые start/stop/restart postconditions.

Эксперимент не материализует A.012 или D.001 в рабочем продукте.

## Вопрос

Нужен ли управляемому WireGuard отдельный systemd-сервис, или его базовую реализацию можно
безопасно и наблюдаемо поддерживать непосредственно как принадлежащий VPN-GATE kernel
WireGuard-интерфейс?

Проверяется кандидат, в котором D.001:

1. читает закрытый ключ только из предварительно проверенного файла;
2. создает WireGuard-интерфейс непосредственно через Linux networking API/tools;
3. ставит наблюдаемый `ifalias` как технический marker принадлежности;
4. применяет базовую WireGuard-конфигурацию через stdin, не сохраняя сгенерированный файл;
5. свежим наблюдением подтверждает exact postcondition;
6. при той же exact конфигурации ничего не пересоздает;
7. при изменении базового поколения удаляет только подтвержденно принадлежащий интерфейс и
   создает его заново;
8. не усыновляет и не удаляет интерфейс того же имени без подтвержденного ownership marker.

`ifalias` здесь проверяется как marker обнаружения собственного объекта, а не как security
boundary против администратора root.

## Стенд

Один disposable network namespace:

- управляемый интерфейс `wg0`;
- один WireGuard peer;
- базовый адрес сначала `10.200.0.1/32`, затем `10.200.0.2/32`;
- постоянный peer probe `10.201.0.1/32`;
- точная транспортная точка `198.51.100.10:51820`;
- принадлежащий эксперименту закрытый ключ в файле mode `0600`.

Payload и handshake не нужны: EXP-087/088 уже доказали peer dataplane. EXP-089 проверяет
только ownership/lifecycle boundary базовой реализации.

## Гипотезы

### H1 — secret-file precondition наблюдаем

Обычный файл, принадлежащий effective UID и не имеющий group/other permissions, принимается.
Тот же файл с mode `0640` отвергается. Symbolic link отвергается.

### H2 — чужой объект того же имени не усыновляется

Если `wg0` уже существует без ожидаемого ownership marker, попытка converge-present
завершается конфликтом и не изменяет/не удаляет этот интерфейс.

### H3 — start подтверждает полный базовый postcondition

Из состояния absent создается WireGuard `wg0`, которому устанавливается ожидаемый
`ifalias`, адрес, public identity, listen port, peer endpoint и постоянный probe `/32`.
Успех возвращается только после нового наблюдения всех этих фактов.

### H4 — повторный start идемпотентен

Повторное converge-present с тем же desired generation сохраняет тот же ifindex и не
пересоздает интерфейс.

### H5 — изменение базового поколения использует stop -> absent -> start

При изменении базового адреса подтвержденно принадлежащий `wg0` удаляется, отсутствие
подтверждается, затем создается новое поколение и подтверждается новый exact postcondition.
Конкретное значение ifindex фиксируется как наблюдение, но его изменение не является
универсальной гарантией Linux.

### H6 — stop удаляет только принадлежащий объект

Converge-absent удаляет интерфейс только при совпадении ownership marker и ожидаемого
WireGuard kind. Чужой `wg0` остается на месте и дает conflict.

## Решение после результата

PASS позволит выбрать для WireGuard D.001 прямую kernel-realization без отдельного
WireGuard systemd unit. Это не отменяет systemd lifecycle для OpenVPN/OpenConnect/L2TP,
если их собственный интеграционный контракт требует отдельного процесса или службы.

До review результата mechanism не переносится в нормативную архитектуру.
