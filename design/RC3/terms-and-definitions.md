# VPN Gateway — термины и определения

**Статус:** нормативный проектный документ  
**Версия:** RC3  
**Дата:** 2026-11-09

Документ задаёт предпочтительную терминологию для архитектуры, журнала экспериментов,
документации и последующей реализации VPN Gateway.

Правила применения:

- в обычном русском тексте используется предпочтительный русский термин;
- если буквальная замена ухудшает смысл или делает фразу громоздкой, при первом употреблении
  в логическом блоке допускается форма «английский термин (русское значение)», после чего
  английский термин может использоваться до конца этого блока;
- технические идентификаторы, имена классов, свойств, цепочек, состояний, команд и полей
  конфигурации не переводятся;
- для исключений, перечисленных ниже без русского эквивалента, английский термин является
  нормативным;
- если русских вариантов несколько, первый является предпочтительным, если контекст не
  требует иного.

| Английский термин | Русский термин | Значение |
|---|---|---|
| runtime | — | Период работы процесса после его запуска, а также состояние системы в этот период. |
| startup | запуск | Последовательность действий от старта процесса до перехода в рабочий режим. |
| cleanup | очистка | Удаление ресурсов проекта из ядра и выключение IPv4-маршрутизации, когда это предусмотрено жизненным циклом. |
| daemon | — | Долгоживущий процесс `vpn-gatewayd`, управляющий ресурсами VPN Gateway. |
| selector | селектор | Правило выбора одного или нескольких имён интерфейсов. |
| exact selector | точный селектор | Селектор, соответствующий одному конкретному имени интерфейса. |
| prefix-family selector | префиксный селектор | Селектор пространства имён интерфейсов с общим префиксом; в конфигурации записывается как `prefix+`. |
| binding | привязка | Связь профиля с найденным интерфейсом. |
| concrete binding | жесткая привязка | Однозначная привязка профиля к конкретной паре имени интерфейса и `ifindex`. |
| binding transition | смена привязки | Появление, исчезновение, замена интерфейса либо изменение однозначности его выбора. |
| readiness / ready | готовность / готов | Состояние профиля, при котором существует единственная жесткая привязка и на интерфейсе присутствует ожидаемый локальный IPv4-адрес. |
| absent | отсутствует | Состояние, при котором селектор не нашёл ни одного подходящего интерфейса. |
| ambiguous | неоднозначен | Состояние, при котором селектор одновременно соответствует более чем одному интерфейсу. |
| reconciliation | согласование | Сопоставление требуемого и фактического состояния с последующим приведением управляемых ресурсов к требуемому состоянию. |
| reconciliation pass | цикл согласования | Один сериализованный проход чтения состояния, построения требуемой модели, применения изменений и проверки результата. |
| snapshot | — | Зафиксированный набор данных, который считается неизменным в пределах определённого этапа обработки. |
| desired state | — | Состояние управляемых ресурсов, которое должно существовать согласно текущей конфигурации и текущей привязке. |
| actual state | — | Состояние управляемых ресурсов, фактически прочитанное из ядра. |
| owned state | — | Набор ресурсов, принадлежность которых текущему процессу подтверждена после успешной проверки. |
| ownership | — | Ответственность процесса за создание, изменение, проверку и удаление определённого ресурса. |
| daemon-owned | — | Относящийся к ресурсам, находящимся под управлением `vpn-gatewayd`. |
| foreign | сторонний, чужой | Ресурс, не находящийся под управлением `vpn-gatewayd`. |
| policy | политика | Требуемая совокупность правил фильтрации, преобразования адресов и связанных ограничений. |
| structural policy | структурная политика | Часть политики, существующая независимо от текущей жесткой привязки. |
| binding-specific | зависящий от привязки | Ресурс или правило, существующее только для текущей жесткой привязки. |
| materialize | применить, создать в ядре | Создать или привести реальные ресурсы ядра к вычисленному требуемому представлению. |
| verify | проверить | Повторно прочитать фактическое состояние и подтвердить его соответствие требуемому. |
| canonical | канонический | Имеющий единственную принятую форму представления для сравнения. |
| canonicalization | приведение к каноническому виду | Преобразование представления ресурса к форме, используемой для однозначного сравнения. |
| drift | дрифт, рассогласование | Расхождение между фактическим и требуемым состоянием. |
| repair | восстановление, исправление | Приведение обнаруженного рассогласованного состояния к требуемому. |
| fail closed | отказ с запретом | Поведение, при котором ошибка или неопределённость закрывает управляемый трафик вместо предоставления обходного пути. |
| fail hard | жёсткий отказ | Поведение, при котором ошибка прерывает запуск или операцию вместо продолжения в частично определённом состоянии. |
| fallback | — | Автоматический или непреднамеренный переход к иному пути или механизму при недоступности основного. |
| failover | — | Намеренное переключение на резервный рабочий путь или экземпляр. |
| guard | защитное правило | Правило, заранее запрещающее небезопасный трафик или состояние. |
| isolation filter | изолирующий фильтр | Полная промежуточная политика фильтрации без разрешающих правил, зависящих от привязки. |
| barrier | защитный барьер | Проверенное безопасное промежуточное состояние, через которое проходит восстановление. |
| wildcard | шаблон по префиксу | Сопоставление группы имён по общей начальной части; в iptables для интерфейсов используется завершающий `+`. |
| namespace | пространство имён | Совокупность имён интерфейсов, относящихся к одному префиксному селектору. |
| terminal verdict | окончательное решение | Решение `ACCEPT`, `DROP` или `REJECT`, после которого дальнейшая обработка пакета в данной цепочке не продолжается. |
| ingress | входящий трафик | Трафик, поступающий через рассматриваемый интерфейс. |
| egress | исходящий трафик, выходной интерфейс | Направление выхода пакета либо интерфейс, через который пакет покидает шлюз. |
| protected destination | защищаемое назначение | Сеть назначения из конфигурации профиля, доступ к которой должен проходить только по управляемой политике VPN Gateway. |
| transport network | транспортная сеть VPN | Адресная сеть, используемая самим VPN-соединением между его сторонами. |
| full resync | полная пересверка | Полное повторное чтение состояния после потери событий или сомнения в актуальности локальной модели. |
| event loop | цикл обработки событий | Единственный сериализованный механизм обработки сетевых событий, таймера, административных команд и завершения процесса. |
| wakeup signal | сигнал пробуждения | Событие, требующее начать согласование, но само по себе не являющееся достоверным описанием текущего состояния. |
| dirty signal | признак необходимости пересверки | Признак того, что сохранённое представление состояния может быть устаревшим. |
| threat model | модель угроз | Явно принятые предположения о возможностях нарушителя и доверенных компонентах системы. |
| reaction window | окно реакции | Интервал между изменением состояния ядра и обработкой этого изменения процессом. |
| prefix | префикс | Начальная часть имени или сетевого адреса, используемая для группировки или сопоставления. |
| overlap | наложение, пересечение | Ситуация, в которой два диапазона, селектора или области маршрутизации могут охватывать один объект. |
| strict parser | строгий разбор | Разбор, при котором неизвестная или неподдерживаемая форма считается ошибкой и не пропускается молча. |
| marker | маркер владения | Зарезервированный признак, по которому ресурс проекта можно отличить от стороннего. |
| target validation | проверка на целевой системе | Практическая проверка поведения команды или интерфейса ядра на целевой версии Debian перед закреплением этого поведения в реализации. |
| CLI | — | Интерфейс командной строки и конкретные формы вызова системных утилит. |

## Технические идентификаторы и именованные состояния

Имена `INPUT`, `FORWARD`, `ACCEPT`, `REJECT`, `DROP`, `MASQUERADE`, `SAFE`,
`UNSAFE`, `UNKNOWN`, `ACTIVE`, `DEGRADED`, `ISOLATED`, `RouteSpec`, `ifindex`,
`Netlink`, `iptables`, `systemd` и аналогичные технические идентификаторы не переводятся.

При первом употреблении именованного состояния в логическом блоке текста следует по
возможности дать его смысл по-русски, если без этого значение неочевидно.
